# TravelPlanner (9Router Research Adaptation)

This repository is a modified research adaptation of the official [TravelPlanner benchmark](https://github.com/OSU-NLP-Group/TravelPlanner) (ICML 2024: *"TravelPlanner: A Benchmark for Real-World Planning with Language Agents"*). 

The primary purpose of this fork is **academic and experimental research** on multi-agent and sole-planning evaluation pipelines using local routing gateways, specifically [9Router](https://github.com/9router/9router).

---

## Key Modifications for 9Router Integration

1. **Local Gateway & Multi-Provider Support (`9Router`):**
   - Seamlessly routes all LLM calls through `OPENAI_API_BASE=http://127.0.0.1:20128/v1`.
   - Supports heterogeneous multi-provider models (e.g. GitHub Copilot `gh/gpt-4.1`, `gh/gpt-4o`, Kiro `kr/claude-sonnet-4.5`, Antigravity `antigravity/gemini-3.8-flash-high`).

2. **Subset & Range Execution (`--query_indices`):**
   - Added `--query_indices` flag across all stages (`tool_agents.py`, `sole_planning.py`, `parsing.py`, `element_extraction.py`, `combination.py`, `eval.py`).
   - Allows flexible testing on specific ranges (e.g. `1-10`, `1-55`, `1,3,5-8`) without forcing a full 180-query run.

3. **Decoupled Parser Model (`--parser_model_name`):**
   - Decoupled the plan-generation model from the markdown-to-JSON format parsing model in `postprocess/parsing.py`.
   - Enables using cost-efficient models (e.g. `gh/gpt-4o-mini`) to parse outputs generated by expensive models (e.g. `kr/claude-sonnet-4.5`), conserving quota.

4. **Auto-Resume & Resilient Execution:**
   - Both `tool_agents.py` and `sole_planning.py` automatically skip already-completed non-empty queries.
   - Built-in retry handling for transient network issues and gateway errors.
   - Fixed `element_extraction.py` to accept raw JSON lists (`[...]`) in addition to markdown code blocks.

5. **Subset-Accurate Evaluation (`eval.py`):**
   - Correctly calculates Delivery Rate, Commonsense, and Hard Constraint Pass Rates strictly over the specified query subset.
   - Added `--output_json_path` to export detailed evaluation metrics into JSON.

## Quick Start

### 1. Environment Setup

Create `.env` in the repository root:
```env
OPENAI_API_BASE=http://127.0.0.1:20128/v1
OPENAI_API_KEY=your_api_key_or_dummy
```

Activate the conda environment:
```bash
conda activate travelplanner
```

---

### 2. Running Pipelines

#### Option A: Two-Stage Mode (Tool-Augmented Agents)
```bash
cd agents

python tool_agents.py \
  --set_type validation \
  --model_name gh/gpt-4.1 \
  --output_dir output_validate/output_gpt41 \
  --query_indices 1-10
```

#### Option B: Sole-Planning Mode (Direct / CoT / ReAct / Reflexion)
```bash
cd tools/planner

python sole_planning.py \
  --set_type validation \
  --model_name gh/gpt-4.1 \
  --strategy direct \
  --output_dir ../../agents/output_validate/output_gpt41_sole \
  --query_indices 1-10
```

---

### 3. Postprocessing (Convert & Combine)

```bash
cd postprocess

# Step 1: Parse Markdown to JSON (supports --parser_model_name)
python parsing.py \
  --set_type validation \
  --model_name gh/gpt-4.1 \
  --output_dir ../agents/output_validate/output_gpt41 \
  --query_indices 1-10

# Step 2: Extract structured JSON into plan files
python element_extraction.py \
  --set_type validation \
  --model_name gh/gpt-4.1 \
  --output_dir ../agents/output_validate/output_gpt41 \
  --query_indices 1-10

# Step 3: Combine into submission .jsonl
python combination.py \
  --set_type validation \
  --model_name gh/gpt-4.1 \
  --output_dir ../agents/output_validate/output_gpt41 \
  --query_indices 1-10
```
*(For Sole-Planning, add `--mode sole-planning --strategy <direct|cot|react|reflexion>` to each command above).*

---

### 4. Evaluation

```bash
cd evaluation

python eval.py \
  --set_type validation \
  --evaluation_file_path ../postprocess/submission/validation_gh_gpt-4.1_two-stage_submission.jsonl \
  --query_indices 1-10 \
  --output_json_path ../postprocess/submission/validation_gh_gpt-4.1_two-stage_eval_results.json
```
